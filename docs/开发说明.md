# 开发说明

本文面向开发者，只描述当前代码的结构、数据流、核心机制、接口与扩展点。功能限制见 [README.md](../README.md) 和 [使用手册](使用手册.md)（反代配置在其“固定 HTTPS 配置”一节），开发规范见 [AGENTS.md](../AGENTS.md)，版本变化见 [CHANGELOG.md](../CHANGELOG.md)。

## 1. 整体结构与数据流

Bot-Call 由 AstrBot 进程内宿主、自托管 HTTPS/WebSocket 通话服务及后台左侧菜单两页面组成：

```text
通话：QQ 私聊发起 (/botcall 或 bot_call_start) → 邀请链接 (#invitation=...) → 手机页采音与 VAD (capture.js / vad.js)
    → 上传落库 (chunk_upload.py → store.py) → STT (astrbot_audio.py) → 来源会话主 Agent (call_history.py / astrbot_agent.py)
    → TTS 流式或整句合成 (segments.py / astrbot_tts.py / streaming_tts.py) → 网页播放 (push.py / pcm.js / call.js)
挂断：尾段结算冻结 (end_call → reviews) → 分块归约回顾 (review_plan.py / review_work.py / astrbot_review.py)
    → 自然段分页发回原会话 + 写回原会话上下文 (publication.py / astrbot_context.py)
```

运行时分两层：**业务事件循环**（`bot_call/plugin.py:PluginLifecycle`、`bot_call/native_host.py:NativeCallbacks` 与各适配模块仅在此访问 `Context`、会话锁与 Provider）和**单一存储线程**（`bot_call/runtime.py:CallRuntime` 独占 `BotCall:storage` 线程操作 `bot_call/store.py:Store`，先落库认领再桥接回业务循环调外部服务，事务不跨 `await`）。

## 3. 关键流程

- **通话生命周期**：`/botcall` 或 `bot_call_start`（`bot_call/native_host.py:tool_entry` 验发起短语、权限与原会话）经 `PluginLifecycle` 预检 STT/TTS/聊天模型后，由 `CallBackend` 在会话锁下建 `CallBinding`、冻结 `CallPolicy` 并签发 15m `#invitation=` 链接。页面调 `exchange` 换 `__Secure-bot_call` Cookie 与 `x-bot-call-reference`，激活 `RuntimeLimits`（3600s 上限、300s 提醒、120s 断线保留，插件运行时启用 `DEFAULT_IDLE_SECONDS=600` 接通后空闲自动挂断；心跳仅延续断线窗口不重置空闲计时，在途分片、转写、回复、工具与播报期间暂停空闲计时，空闲与双死线共用单一 `_limit_handle`）。挂断、超限或管理员 `force_end_call` 均由 `end_call` 结算尾段、保留既有发言回顾并立即释放单线；首声前工具执行通过内存 `_active_tools` 实时推送 `WebCallState.tool_processing`（不外泄工具名），前端明确展示不可插话态、麦态区分与满 3 秒本地 WebAudio 轻提示音；热重载时 `_initialize` 用 `_is_orphan` 等旧实例释放端口后再接管。
- **采音、VAD、分段与续说**：`call_capture_mode` 为 `auto` 时，`ContinuousCapture` 维持静音 `CaptureProcessor` 常驻并留约 0.5s 48 kHz 预录环。`LocalVAD`（Silero v5 + 能量兜底）检出起声后，预录与实时帧送 `bot_call/static/capture-worker.js` 编为 24 kbps Opus/WebM（单次 ≤50 ms 缺口补零，单段 ≤200 ms）；编码异常依次按离线 Opus、`OfflineAudioContext` 16 kHz WAV、静音图 `MediaRecorder` 恢复，不支持则退回 `legacy` `MediaRecorder`。静音达 `call_vad_silence_ms`（默认 1200 ms）切段，冷启动片段经 `classifyPCM` 复核。分片经 `audio-chunk` / `audio-commit` 验 SHA256 入库，`convert_stt_audio` 转 16 kHz WAV 后调 `get_text`。满 30s 无缝续录（上限 `call_max_continuous_segments` 段），`SeriesStore` 待整组密封且转写全成功后由 `effective_transcript` 合并触发一次回复。
- **插话与附和续播**：持续采音且 `call_barge_in` 为 `auto` 时，朗读期连续 5 帧语音概率 ≥ 0.65 触发 `BargeMethods` 25 ms 降增益至 0（软暂停上限 6s / 1 MiB）并报 `barge-in`（`begin`）；语音满 1200 ms 发 `long_speech` 停旧朗读。候选沿用配置的 `call_vad_silence_ms` 统一停顿切段且只转写一次，`bot_call/barge_in.py:decide_candidate` 判定：空转写，或非问句、非末句最后 1000 ms 的 `"middle"` 位置、非长语音且仅含 `call_backchannel_phrases` 时，判 `resume` 续播并记备注；否则判 `interrupt`，按已播毫秒截断旧句（`playback_projection`）并调 `SourceAgent` 的 `interrupt`（等在途工具收尾后停旧轮次并派发新发言）。若 `barge-in` `begin` 注册因弱网/切网超时失败，前端不遮蔽主屏重试入口且延迟未确认的 `cancel`；重试与挂断统一先读权威 `GET /bot-call/state`，按服务端候选与旧句终态补发 `timeout`/`cancel` 或解绑并以原片段 ID 续传（已收片段幂等确认）。进入关闭态（本地挂断或服务端关闭）时仅递增一次页面 `epoch`，避免 WS 推送循环重复拉取状态。
- **流式合成与整句回退**：`SourceAgent` 建 `"live"` 标记的 `PhoneEvent` 并开流式输出（`phone_stream_config`）。增量经 `Sentences` 去思考切句（首句满 6 字词字符遇逗号/分号提前切出，后续按句末标点或约 60 字切分），经 `PhonePlainText` 去 Markdown 后入队 `SegmentRuntime`。首句若有唯一声明 `bot-call.pcm-v1` 的 WebSocket 且满足 `tts_stream_settings`（依次匹配 `dashscope_stream_settings`：`dashscope_tts` 非空模型排除 `sambert*`/`*-realtime`/Qwen HTTP；以及 `openai_stream_settings`：`openai_tts_api` 按域名区分 OpenAI 官方 24 kHz `pcm`、硅基流动 `wav`+`sample_rate=24000`、其他自建/反代端点标准 `wav`，发声前强校验 24 kHz / 单声道 / 16-bit PCM 头且禁止重定向），`AstrBotTTSAdapter` 调 `bot_call/streaming_tts.py:stream_sentence`（5s 建连超时，优先校验单 Provider `proxy` 再走 `resolve_proxy` 支持 HTTP/HTTPS 代理与 `NO_PROXY`），经 `PCMDelivery` 推 24 kHz PCM 供 `PCMPlayer` 播放，结束后归档 32 kbps MP3；首包前失败记 `tts_stream_fallback` 并回退一次 `get_audio`（同一通话内 `proxy_unsupported`（2）、`task_failed`（6，百炼任务拒绝或 OpenAI 4xx）与 `format_unsupported`（7，非 24 kHz/单声道/16-bit PCM 或非音频响应）首次即熔断，其他首包前错误连续 2 次熔断，本通后续轮次直接记 `circuit_open`（5）走 `get_audio`，流式成功则清零），已下发后中断标未知不重发。延迟评测探针（`BenchmarkController.probe`）在首包前流式失败时同样回退一次 `get_audio` 并展示回退提示，已收音频后中断不回退。后续句与非流式路径走 `get_audio` 转 MP3（首句 ≤48 KiB 可内联 `first_audio`）。
- **回顾任务与重试**：`end_call` 冻结转写、播放观测（播完/仅开始/未播）、工具报告与续说限制进 `reviews`。`build_review_plan` 按窗口切 `map` 节点，`advance_review_work` 按 `map → merge → final` 调 `Context.llm_generate`（`request_max_retries=1`）：明确拒绝经 `definite_review_failure` 记 `failed`，超时或异常记 `uncertain` 不自动重试。完成后 `advance_publication` 按自然段分页（默认 1800 字）发回原会话，`AstrBotContextAdapter` 写回历史。失败或未知回顾可在诊断页（`retry_review`）或管理接口 `/reviews` 经 `AttemptStore`（`bot_call/review_retry.py`）建独立尝试，默认 `context_only` 只写记忆不补发消息。
- **接入方式校验**：`NativeServer` 在 `listen_port`（默认 6191）跑 Hypercorn 并套 `HostASGI`。`quick_tunnel` 强制绑定且只信 `127.0.0.1`，由 `QuickTunnel` 经 `_tunnel_env`（仅白名单继承 `PATH` 与大小写代理变量，继续隔离 `TUNNEL_*`/配置目录/凭据/加载器变量）拉起 `cloudflared` 等临时域名与注册确认；`fixed_https` 按 `listen_host` 监听，逐请求核查：① socket peer 命中 `trusted_proxies`（`bot_call/proxy_access.py:trusted_peer`，不读 `X-Forwarded-For`，禁 `/0`）；② 唯一 `X-Forwarded-Proto: https`；③ `Host`（及 POST/WS 的 `Origin`）等于 `public_origin`，拒绝写入 `Rejections`。

## 4. AstrBot 兼容层

仅 `bot_call/astrbot_compat.py` 可导入 `astrbot` 或访问框架私有属性（`tests/test_astrbot_compat.py` AST 守卫），既把 `build_main_agent`、`run_agent`、`_dashboard_server` 等内部接口收敛单处，又让核心状态机和存储层零框架耦合、可独立单测。

支持版本 `SUPPORTED_VERSIONS = ">=4.27.2,!=4.28.*"`，已验证范围 `VERIFIED_VERSIONS = ">=4.27.2,<4.30,!=4.28.*"`（`BASELINE_VERSION = "4.27.2"`）。`astrbot_version_status` 区分 `verified` / `unverified_newer` / `unsupported`：4.30 及以上由 `new_agent_config` 去重告警放行并在安装自检标 `warn`。适配点：`new_agent_config` 区分 4.27.2 `provider_settings` 与 4.29+ `agent_runner`（仅 `local`）；`build_config` 按 `MainAgentBuildConfig` 的 `init` 字段交集传参；`_supports_plugin_page_post` 在运行时探测插件扩展 POST 路由与 `plugin_page_bridge.js` 资源（缺失时控制面板安全退为只读，不再读取框架源码文本）；`using_provider` 优先异步选择器；`PhoneHooks` 管钩子派发与跳过；`dashboard_authorized` 验管理 JWT 且要求 POST 带匹配的 `Authorization: Bearer`。新增已验证版本：核对上述接口签名后更新 `VERIFIED_VERSIONS`（保留 `ESTIMATE_RULE` / `COUNTER_RULE` 兼容冻结回顾），再跑通 `tools/run_tests.sh` 与 `tools/staging.sh`。

## 5. 数据与存储

SQLite 库 `calls.sqlite3` 位于插件数据目录（`PRAGMA user_version=24`，31 张表）：

| 分组 | 表名 | 用途 |
| --- | --- | --- |
| 通话与凭据（6） | `calls`、`call_policies`、`call_limits`、`call_closures`、`web_invitations`、`web_sessions` | 通话绑定、策略指纹、死线、关闭请求、邀请与会话令牌哈希。 |
| 通话材料（9） | `turns`、`generations`、`audio_jobs`、`audio_missing_policies`、`audio_resolutions`、`speech_jobs`、`speech_segments`、`barge_candidates`、`agent_runs` | 轮次、生成认领、上传与续说、缺失决议、整段/分句音频与播放观测、插话候选、工具报告。 |
| 耗时指标（1） | `turn_timings` | 分段耗时、token、历史字数、回退/插话编码及前端采音与回声指标。 |
| 回顾与重试（10） | `reviews`、`review_work`、`review_work_nodes`、`review_work_stages`、`review_policy_manifests`、`review_audio_notes`、`review_agent_notes`、`review_retry_attempts`、`review_retry_nodes`、`review_retry_stages` | 冻结回顾输入与正文、归约计划/节点/阶段、策略清单、缺失与工具备注，及重试尝试/节点/阶段。 |
| 投递与旧版（5） | `publications`、`publication_pages`、`query_policies`、`query_attempts`、`review_query_notes` | 上下文写回与分页进度；后 3 张为旧工具查询只读表。 |

- **迁移原则（只增不改）**：按 `user_version` 只增表、触发器或可空/带默认值列，不改旧行；设 `immutable_call`、`immutable_turn`、`retained_audio` 等触发器防篡改删除，仅向前升级，高版本库拒绝启动。
- **音频留存与空间回收（`bot_call/retention.py`）**：`CallRuntime` 通过 `call_later` 在启动 60s 后首检、每小时巡检（积压 5s 续批，活跃通话或锁竞争避让 300s），仅对回顾与发布已终结（普通成功发布、重试补做发布或按选择仅写聊天记忆、无正文正常关闭）且超过 `audio_retention_days`（默认 7 天，0 关闭）的通话，按小批短事务（最多 10 通/轮、200 行/事务）释放 `speech_segments.data`、`speech_jobs.data`（置 `NULL`）及失败/取消/未知 `audio_jobs.data`（置 `X''`，由 schema 24 的 `audio_progress` 触发器在引擎层强制校验终态，保留文字、播放观测、回顾与缺失决议元数据）。新库建表前启用 `auto_vacuum=INCREMENTAL` 并按每次最多 256 页增量回收；旧库仅在空闲、空闲页达阈值且磁盘余量充足时一次性转为增量模式并缩容，WAL 模式下执行非阻塞 `PASSIVE` checkpoint。
- **日志原则**：外部调用包在 `ProviderLogPrivacy`（`bot_call/sdk_privacy.py`）内过滤框架与 SDK 日志，`PhoneTrace` 丢弃原生 trace；日志只记阶段、错误码、耗时与哈希前缀，不记正文、音频或凭据。

## 6. HTTP/WS 接口概览

### 6.1 通话页接口（前缀 `/bot-call/`，`bot_call/web.py:CallWebApp`、`bot_call/push.py:websocket`）

通话页入口 `GET /bot-call/` 忽略 URL 查询参数（不解析、不回显、不记录），其余静态资源、API 与 WebSocket 仍拒绝非空查询参数；除静态资源和 `exchange` 外，均校验 `__Secure-bot_call` Cookie 与 `x-bot-call-reference`：

| 子路径 | 方法 | 用途与代码位置 |
| --- | --- | --- |
| `/bot-call/` 及静态资源 | GET | HTML/CSS/JS、试听音频及 `bot_call/static/vendor/` 下 VAD/WASM。 |
| `exchange` | POST | 用 `invitation` 换 Cookie、`reference` 与体验参数。 |
| `state` | GET | 读 `WebCallState`（`bot_call/access.py:WebCallState`），支持 ≤8000 ms 长轮询。 |
| `audio-chunk`、`audio-commit`、`audio` | POST | 分片上传、尾块加 SHA256 提交或整段上传（`bot_call/chunk_upload.py`）。 |
| `audio-series`、`audio-series-commit`、`audio-series-control` | POST | 30s 续说上传/提交及 `seal` / `abandon` 控制（`bot_call/series.py`）。 |
| `audio-resolution` | POST | 未识别保留音频确认跳过或重录。 |
| `barge-in` | POST | 朗读候选插话上报（`bot_call/barge_in.py:valid_request`）。 |
| `segment-audio`、`segment-playback` | POST | 拉单句 MP3 及报播放状态与 `first_sound_ms`。 |
| `speech`、`speech-audio`、`playback` | POST | 未分句时的整轮 WAV 等待、拉取与回执。 |
| `utterances`、`heartbeat`、`end` | POST | 文本提交、心跳续期与挂断。 |
| `metrics` | POST | 报前端耗时、采音与回声指标（`bot_call/observability.py:client_metric_valid`）。 |
| `/bot-call/ws` | WS | 状态推送与首句 PCM 流；子协议 `bot-call.<reference>` 及可选 `bot-call.pcm-v1`。 |

## 9. 已知的设计取舍与限制

- **全局单线通话**：`exchange_web_invitation` 在已有活跃通话时返回 `busy`（通话页识别白名单错误码并保留邀请支持重试）。插件与 AstrBot 同进程共用 CPU/内存与会话锁，单通防转码、PCM 流与工具循环争抢拖慢首声；接通后默认 10 分钟无发言自动挂断，且管理页支持查看占线元数据并管理员 `force_hangup` 立即释放单线（含重载后遗留占线）。
- **流式合成范围与回退**：公共 `TTSProvider` 只有整句 `get_audio`，当前仅对百炼 `dashscope_tts` 双向流式协议与 OpenAI 兼容 `openai_tts_api` `/audio/speech` HTTP chunked 流式做 24 kHz PCM 直推（`bot_call/streaming_tts.py`）；其余 TTS、采样率/格式不符 24 kHz 单声道 16-bit PCM 或 SOCKS 代理均自动走整句合成，不为未验证服务硬编码私有协议。
- **iPhone 流式播放与整句回退**：非 UA 屏蔽。为让 Android 开麦后走系统通话音频流，`CallPage`（`bot_call/static/call.js`）等 `getUserMedia` 完成后才建播放 `AudioContext`（`preparePCM`）；`canReceivePCM` 要求该上下文处于 `running`。iPhone QQ 少量真机实测中 `AudioContext` 正常处于 `running` 并已跑通首句流式 PCM；仅当特定 iOS 场景下音频上下文挂起（如后台切回或未获手势激活）时，才不声明 `bot-call.pcm-v1` 而自动退回整句 MP3 + `HTMLAudio`。
- **未知结果不自动重试**：STT、模型、TTS、回顾与外发消息超时或中断时无法证明未扣费或未送达，记 `uncertain` 留材料待显式处理，防重复计费或副作用。
- **通话期不写原会话，回顾沿用来源模型**：通话只读原会话裁剪副本（`CallHistory`），挂断后一次性写回回顾，防碎句污染聊天；回顾用来源模型保证归纳质量。
