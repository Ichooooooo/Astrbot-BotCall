## 功能详解

- **边听边说、自动断句**：默认的自动录音模式会在你刚开口前多保留约半秒声音，避免吞掉第一个字；你说完停顿片刻就会自动发送给机器人。如果一口气讲得很长，系统每约 30 秒会自动分段识别，等你整段说完再合并回复。
- **随时插话打断**：机器人正在说话时你可以直接开口，页面会先暂停机器人声音再识别你说的内容。如果是真的插话，就会停掉旧回复、直接回答你的新问题；注意机器人之前已经做完的工具操作不会自动撤销，正在执行的后台工具也会等它安全收尾。
- **随口附和可续播**：机器人讲述途中如果你只是顺口说“嗯、对、好的”这类短附和词，识别确认后会从刚才停下的位置接着往下读；如果机器人刚问了你问题、刚说完一轮，或者不确定你是不是在附和，系统会稳妥地按正常发言处理。该功能按文字和上下文判断，不是声纹识别，外放回声过大时仍可能误触发。
- **逐句朗读与首句边生成边播**：机器人回复一句、播一句。如果你用的是**阿里云百炼**（如 CosyVoice 系列等支持实时音频流的模型）或 **OpenAI 兼容格式语音合成**（如 OpenAI 官方、硅基流动 CosyVoice2 及其他兼容服务），第一句话还能边生成声音边播放，开口更快；后续句子按顺序衔接。如果所选服务或模型不支持实时语音流、代理受限或被服务商拒绝，插件会在出声前自动切回普通整句播报，并且在这通电话里不再反复尝试超时（硅基流动 `FunAudioLLM/CosyVoice2-0.5B` 实测约 0.3 秒即可听到第一句开头声音）。
- **挂断后自动回顾**：挂断电话后，系统会把这通电话服务端收到的完整对话整理成一份清晰的回顾，区分你的想法、机器人的建议、已经定下来的事以及未确认的事项，发回原来的 QQ 聊天并写入聊天记忆。
- **控制面板与评测诊断**：在 AstrBot 管理后台可以直接修改所有设置、查看最近 30 通电话的分段耗时并与参考速度做对比，还可以一键测试各服务连通情况、检查安装条件。

**适用范围**：AstrBot **>=4.27.2，不含 4.28.x**（已完整验证 4.27.2 与 4.29.x；4.30 及以上版本会记录兼容性提醒并照常加载，如果新版本不支持在控制面板直接保存，页面会自动切为只读并提示改用 AstrBot 原生插件设置页）。AstrBot 需使用默认的本地运行模式（未切换到外部代理运行器）。支持官方 QQ 和 OneBot 私聊入口，目前主要在 Android 官方 QQ 前台完成了完整实测；iPhone QQ 做过少量实测（支持首句边生成边播，浏览器暂时拦截自动播放时会自动改回整句播报），暂未做全场景覆盖；OneBot 暂未做真机实测。

**手机与通话限制**：需要手机浏览器支持 HTTPS 网页录音和声音播放，且通话期间保持页面在前台（锁屏、切后台或系统省电可能会中断收音）。默认的自动录音与插话功能依赖浏览器持续收音能力，老旧浏览器不支持时会自动降级为普通录音模式（此时变为轮流说话，不能在机器人朗读时插话）。每人同时最多一通，整个插件同一时间只允许一通电话，单通最长 60 分钟；接通后如果连续 10 分钟没有任何有效发言会自动挂断（正在说话、识别、思考、调用工具或朗读期间不会误挂）；网络闪断后保留约 2 分钟的重连机会。

## 安装与配置

1. 在 **AstrBot 实际运行环境内**安装 `ffmpeg`，确认命令行能直接运行，并支持 MP3 音频编码（`libmp3lame`）。可运行 `ffmpeg -version` 和 `ffmpeg -encoders` 自检。用 Docker 部署时，装在宿主机上不等于容器里能用；插件不会代装系统软件。
2. 获取 Bot-Call 安装包（ZIP），在 **AstrBot 管理后台 → 插件管理 → 上传安装**，保持版本检查开启。请上传正式打包好的 ZIP，不要直接把整个源码文件夹打包上传。
3. 在 AstrBot 中添加并启用聊天模型、语音识别（STT）和语音合成（TTS）服务，并为要发起通话的**原 QQ 聊天窗口**选好默认服务。所有 API 密钥只填在 AstrBot 自带的服务管理里，插件不单独保存密钥。聊天模型需支持工具调用；机器人的人格设定和工具权限默认沿用原 QQ 聊天设置。
4. 选择手机访问的 HTTPS 接入方式：想先试试效果可用**临时隧道**（见下节）；打算长期稳定使用推荐**固定 HTTPS**（见[固定 HTTPS 配置](#固定-https-配置)）。
5. 确认两个开关都打开：先在“插件管理”启用 Bot-Call，再打开左侧 **Bot-Call 控制面板** 开启**启用通话功能**，保存并重载插件。默认处于关闭状态，不会提前占用端口。
6. 在控制面板和“评测与诊断”页查看状态正常后，回到 QQ 私聊发送 `/botcall`，用手机点开链接实际打通一轮对话。后台显示就绪只代表服务端准备好了，不等于手机网络与公网入口已经畅通。

**一套实测顺畅的参考搭配**（并非唯一选择，可按需替换）：

| 能力 | 在 AstrBot 里的推荐配置 | 在 Bot-Call 控制面板里的配置 |
| --- | --- | --- |
| 电话聊天模型 | DeepSeek 官方 Flash，在该模型配置里关闭“思考模式” | “电话专用聊天模型”下拉选中它 |
| 语音识别（STT） | 硅基流动 `Qwen/Qwen3-ASR-1.7B`（OpenAI Whisper 兼容语音识别） | “电话专用 STT”下拉选中它，或留空沿用原聊天设置 |
| 语音合成（TTS） | 阿里云百炼 `cosyvoice-v3-flash` 或硅基流动 `FunAudioLLM/CosyVoice2-0.5B` | “电话合成服务”下拉选中它 |
| 接入与语音 | 固定 HTTPS、自动录音、自动插话 | 停顿判停推荐 `1400` 毫秒、灵敏度 `50`（默认）、连续发言最多 `10` 段 |

**关于语音合成（TTS）兼容性**：AstrBot 里支持的语音合成服务都能逐句正常播报。如果要开启第一句“边生成边播放”来缩短等待，目前支持两类服务：① **阿里云百炼**（支持实时语音流的模型如 CosyVoice 系列；不支持实时流的旧型号或仅支持整句接口的型号会自动跳过）；② **OpenAI 兼容接口语音合成**（包括 OpenAI 官方、硅基流动以及常见自建兼容服务，会在出声前自动检查音频格式是否匹配）。只要所选模型不支持实时流、代理受限或被服务商拒绝，系统都会在出声前自动切回普通整句播报，且本通电话不再重复等待超时，后台“一键测试”也会同步回退并给出提示。目前已实机验证通过百炼 `cosyvoice-v3-flash` 和硅基流动 `FunAudioLLM/CosyVoice2-0.5B`（约 0.3 秒即可听到首句开头声音）；OpenAI 官方与其他兼容服务已完成本地模拟测试。使用普通整句播报时，需要等第一句完整生成后才能响起，开口会稍慢一些。

**关于网络代理**：如果服务器需要通过代理访问外网，实时语音合成支持读取常见系统代理环境变量（`HTTPS_PROXY`、`WSS_PROXY`、`ALL_PROXY` 并遵守 `NO_PROXY`），OpenAI 兼容语音合成也支持优先读取该服务条目自己填的代理地址。注意实时流仅支持 HTTP/HTTPS 代理，遇到 SOCKS 代理或建立连接超过 5 秒时会自动切回整句播报。如果某通电话里首句实时播报反复失败，“评测与诊断”页会给出明确提示。

**关于语音识别（STT）兼容性**：已实机验证硅基流动 `Qwen/Qwen3-ASR-1.7B`，其他在 AstrBot 里可用的语音识别服务原则上也都能用。建议在控制面板“电话专用 STT”中明确选定一个已启用的服务；留空时会跟随发起通话的原 QQ 聊天所选服务。如果你指定的语音识别服务被停用或删除，通话会直接报错提醒，不会悄悄替你换用别的服务。

## 临时隧道

最省事的体验方式，不需要买域名或配证书。你只需要在 AstrBot 所在的同一环境（如果是 Docker，需装在同一个容器内）自行安装 `cloudflared` 并确保可以直接执行，插件不会替你自动下载或安装它。

在控制面板将接入方式切为**临时隧道**，或写入以下配置后保存并重载插件：

```json
{
  "access_mode": "quick_tunnel",
  "public_origin": "",
  "cloudflared_path": "cloudflared",
  "tunnel_start_timeout": 30,
  "enabled": true
}
```

如果 `cloudflared` 不在系统默认命令路径里，可以把 `cloudflared_path` 改成它的完整文件路径。临时隧道只在本机 `127.0.0.1` 启动监听，公网网址由 Cloudflare 临时分配，每次重启后地址都可能变化，届时重新在 QQ 私聊发 `/botcall` 获取新链接即可。由于流量经过 Cloudflare，实际速度、地区可达性和首次加载速度可能受网络环境影响。临时隧道免费但无长期稳定性承诺；插件不会在隧道启动失败后擅自切到其他模式。如果运行环境需要经代理联网，插件会自动把常见代理环境变量（`HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` / `NO_PROXY` 及其小写）传给 `cloudflared`，不会泄露其他无关配置或密钥。

## 固定 HTTPS 配置

适合长期稳定使用：准备一个自己的域名（下文用 `call.example.com` 举例），在公网只开放反向代理的 80 和 443 端口，**千万不要把插件的 6191 端口直接暴露到公网**。中国大陆服务器绑定域名对外服务一般需要完成备案，并在云服务器安全组与系统防火墙放行 80 和 443 端口。以下示例中的域名、路径和网段请按自己的实际环境替换。

### 方案一：直接运行 AstrBot，本机 nginx 反向代理

插件配置：

```json
{
  "access_mode": "fixed_https",
  "public_origin": "https://call.example.com",
  "listen_host": "127.0.0.1",
  "listen_port": 6191,
  "trusted_proxies": ["127.0.0.1"]
}
```

nginx 配置示例（证书路径换成你的真实证书，`map` 和 `server` 都写在 `http` 段内）：

```nginx
map $http_upgrade $botcall_connection {
    default upgrade;
    '' close;
}
server {
    listen 80;
    server_name call.example.com;
    return 301 https://call.example.com$request_uri;
}
server {
    listen 443 ssl;
    server_name call.example.com;
    ssl_certificate /etc/nginx/certs/fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/privkey.pem;
    client_max_body_size 4m; # 默认单段录音上限 2 MiB，如调大插件上限需同步调大这里
    location ^~ /bot-call/ {
        proxy_pass http://127.0.0.1:6191; # 末尾不要加斜杠，保留 /bot-call/ 前缀
        proxy_http_version 1.1;
        proxy_set_header Host $http_host;
        proxy_set_header Origin $http_origin;
        proxy_set_header X-Forwarded-Proto https; # 明确覆盖为单个 https，不要重复追加
        proxy_set_header Upgrade $http_upgrade; # 实时语音连接 /bot-call/ws 也走这里
        proxy_set_header Connection $botcall_connection;
        proxy_buffering off;
        proxy_request_buffering off;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
    location / { return 404; }
}
```

如果你更习惯用 Caddy，也可以直接套用方案三的 Caddyfile，只需把代理目标改为 `127.0.0.1:6191`，Caddy 可以自动申请和续期免费 HTTPS 证书。

### 方案二：Docker 运行 AstrBot + 宿主机已有反向代理

在已有 AstrBot 的容器编排配置里增加一条**仅限本机访问**的端口映射（保留你原来的数据目录和其他端口）：

```yaml
services:
  astrbot:
    ports:
      - "127.0.0.1:6191:6191"
```

查一下 AstrBot 容器所在 Docker 网络的网关地址（宿主机反代访问容器时，容器看到的来源 IP 就是这个网关）：

```sh
docker inspect astrbot --format '{{range $name, $net := .NetworkSettings.Networks}}{{$name}} gateway={{$net.Gateway}} ip={{$net.IPAddress}}{{println}}{{end}}'
docker network inspect <上一步查到的网络名> --format '{{json .IPAM.Config}}'
```

假设查到的网关是 `172.18.0.1`，插件配置填为：

```json
{
  "access_mode": "fixed_https",
  "public_origin": "https://call.example.com",
  "listen_host": "0.0.0.0",
  "listen_port": 6191,
  "trusted_proxies": ["172.18.0.1"]
}
```

宿主机反向代理按方案一的 nginx 示例填写，代理目标依然是 `127.0.0.1:6191`。如果使用宝塔或 1Panel 配置站点反代，请确认：只转发 `/bot-call/` 路径、保留原始 `Host` 和 `Origin`、将 `X-Forwarded-Proto` 设为单个 `https`、开启 WebSocket 转发、关闭代理缓存，并将上传大小上限设为 `4m`、超时时间设为 `3600` 秒。

**安全提醒：Docker 映射端口默认会绕过 `ufw` 等系统防火墙，所以必须写成 `127.0.0.1:6191:6191`，切勿写成 `0.0.0.0:6191:6191` 或 `6191:6191`。**

### 方案三：Docker Compose 同时运行 Caddy 与 AstrBot

适合从零搭建；已有部署请合并配置并保留你原来的数据目录。下面示例中的内网网段如果和宿主机现有网段冲突，换一个未占用的即可。Caddy 会自动申请并续期 HTTPS 证书，前提是域名已正确解析到这台服务器，且 80 和 443 端口可从公网访问。

```yaml
services:
  astrbot:
    image: soulter/astrbot:latest
    volumes:
      - ./data:/AstrBot/data
      - ./astra_db:/AstrBot/astra_db
    networks: [botcall]
  caddy:
    image: caddy:2
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    networks: [botcall]
networks:
  botcall:
    ipam:
      config:
        - subnet: 172.28.0.0/24
volumes:
  caddy_data:
  caddy_config:
```

`Caddyfile` 内容：

```caddyfile
call.example.com {
    @botcall path /bot-call/*
    handle @botcall {
        request_body {
            max_size 4MB
        }
        reverse_proxy astrbot:6191 {
            header_up Host {http.request.hostport}
            header_up X-Forwarded-Proto https
            flush_interval -1
            stream_timeout 1h
            transport http {
                read_timeout 1h
                write_timeout 1h
            }
        }
    }
    handle {
        respond 404
    }
}
```

Caddy 默认会自动处理 WebSocket 实时连接转发、保留 `Origin` 且不缓存流式响应；不要改成 `handle_path`，也不要删掉 `Origin` 或重复添加 `X-Forwarded-Proto`。

插件配置：

```json
{
  "access_mode": "fixed_https",
  "public_origin": "https://call.example.com",
  "listen_host": "0.0.0.0",
  "listen_port": 6191,
  "trusted_proxies": ["172.28.0.0/24"]
}
```

### 接入校验与排错要点

- `listen_host` 只接受具体的 IPv4/IPv6 地址，默认是 `127.0.0.1`。如果在 Docker 里设为 `0.0.0.0`（允许容器外访问），可信代理列表就不能只填本机 `127.0.0.1`，需要填入实际的 Docker 网关 IP 或专用子网，否则保存时会拦下并提示。
- `trusted_proxies` 支持填 1～64 个具体 IP 或网段（例如 `172.28.0.0/24`），为了安全，禁止填写匹配所有地址的 `0.0.0.0/0` 或 `::/0`。
- 插件会核对反向代理实际连进来的来源 IP（不轻信外部伪造的转发地址）、确认 HTTPS 标记头恰好为单个 `https`，并核对访问域名与 `public_origin` 完全一致。
- 如果接入被拒，刷新 **Bot-Call 控制面板** 会直接显示“最近一次接入拒绝”的具体原因、代理实际来源 IP 和域名核对情况，照着改最省事。
- 遇到 403 先核对来源 IP 是否在可信代理里、域名是否一致、是否多拼了一层反向代理；实时连接连不上再核对 WebSocket 转发设置。端口能通、证书正常不等于手机真实通话一定没问题，改完请实际打一通测试。

## 插件设置项

控制面板和 AstrBot 原生插件设置页操作的是同一份配置。修改保存并重载插件后，主要对**新发起的通话**生效。重载前建议等当前通话挂断并完成回顾，避免中途打断。

### 接入设置

| 设置项（配置键） | 说明、默认值与建议 |
| --- | --- |
| 启用通话功能（`enabled`） | 默认关闭（`false`）。装完插件、配好接入和语音服务后再打开 |
| 公开接入方式（`access_mode`） | 默认 `fixed_https`（固定 HTTPS）；想先试用免域名方式可改为 `quick_tunnel`（临时隧道） |
| 公开访问地址（`public_origin`） | 固定 HTTPS 时填写你的网址，例如 `https://call.example.com`（只填到域名或端口，后面不要带 `/bot-call`）；默认留空 |
| 监听地址（`listen_host`） | 默认 `127.0.0.1`（仅本机访问）；Docker 部署需要从宿主机反代访问时填 `0.0.0.0` |
| 监听端口（`listen_port`） | 默认 `6191`；切勿直接暴露到公网 |
| 可信代理地址（`trusted_proxies`） | 固定 HTTPS 时允许转发进来的反代 IP 或网段，默认 `["127.0.0.1"]`；每行填一个 |
| cloudflared 路径（`cloudflared_path`） | 临时隧道程序路径，默认 `cloudflared` |
| 隧道启动超时（`tunnel_start_timeout`） | 等待临时隧道启动的秒数，默认 `30`，可填 `1～120` |

### 语音、断句与音频留存

| 设置项（配置键） | 说明、默认值与建议 |
| --- | --- |
| 电话合成服务（`call_tts_provider_id`） | 语音合成服务，默认留空（沿用原聊天设置）。阿里云百炼实时流模型（如 CosyVoice）与 OpenAI 兼容语音合成（如 OpenAI 官方、硅基流动 CosyVoice2 及其他兼容服务）支持第一句边生成边播放，不兼容或被拒绝时自动改回整句播报；其他服务均支持逐句整句播报 |

| 录音方式（`call_capture_mode`） | 默认 `auto`（自动模式，保留开口前约半秒，支持边听边说）；若遇极少数机型不兼容可改为 `legacy`（兼容模式，轮流说话） |

| 自动断句停顿时长（`call_vad_silence_ms`） | 说完话停顿多久判定为讲完，默认 `1200` 毫秒，实测推荐 **`1400`** 毫秒（范围 `300～3000`）。普通说话和插话统一按这个时长判停 |
| 人声检测灵敏度（`call_vad_sensitivity`） | 默认 `50`（范围 `10～90`）。环境较吵容易误收杂音时往回调低，说话轻或麦克风声音小时往上调高 |
| 单段录音大小上限（`max_audio_bytes`） | 单段上传音频大小上限，默认 `2 MiB` |

| 连续说话最多段数（`call_max_continuous_segments`） | 一次连续发言最多自动切几段（每段约 30 秒），默认 `10` 段（约 5 分钟），最多 `20` |

## 开始、插话与结束通话

1. 在已授权的官方 QQ 或 OneBot **私聊**中发送 `/botcall`；也可以直接对机器人说“给我打个电话”，让它自动帮你发通话链接。
2. 用手机浏览器在 15 分钟内点开收到的一次性链接，点击开始并允许使用麦克风，等页面提示“可以说话”后再开口。链接相当于临时门禁，请不要转发给别人。
3. 说完自然停顿片刻就会自动发送，也可以手动点“说完本段”立刻发送。连续讲满约 30 秒会自动切段上传，默认最多连续说 10 段。通话时请保持页面在前台、不要锁屏。
4. 机器人说话时可以直接插话，短附和词识别后会从停点续播；点“停止朗读”只会停掉声音，不会撤销已经执行过的工具操作；点“静音”会关闭麦克风与插话检测，但仍可继续听机器人回复。
5. 聊完点击挂断，稍等最后一段话处理完的提示出现后即可关闭网页，通话回顾会在后台继续整理，整理好后自动发回原 QQ 聊天，你可以接着文字聊。注意：关闭页面前还没传到服务器的语音无法保证找回。

网络短暂闪断时页面会自动重连并同步状态。如果机器人开口前正在调用外部工具（例如搜索或执行插件功能），页面会明确提示“工具处理中…”（或“工具收尾中…”）与“暂不可插话”，并将麦克风按钮与正常收音状态区分开；等待超过 3 秒时手机端会自动播放轻柔的本地提示音（本地生成，不额外产生费用，一旦开口播报或静音立即停止）。如果因为长时间没说话被自动挂断，或者被管理员在后台强制挂断，页面会显示对应原因，此前已经聊完的内容仍会正常整理成通话回顾。

## 控制面板与评测诊断

这两个页面都在 AstrBot 管理后台左侧菜单里，需要管理员账号登录才能查看；手机上点开的通话邀请链接不需要登录管理后台。

- **控制面板**：按“接入”“通话”“语音与断句”“回顾”分组展示，全部可以点选或填表修改。保存后留意页面是否提示需要重载插件；如果固定 HTTPS 接入失败，直接看页面里的“最近一次接入拒绝”就能定位原因。
- **评测与诊断页**：用来集中查看服务是否就绪、当前有没有占线通话、实际生效的模型和语音服务、未完成的回顾状态以及通话耗时。在“当前通话”区域只展示状态、短编号、已持续/无发言/剩余时长和对话轮数（绝不展示聊天正文）；如果遇到有人忘挂占线，管理员经二次确认后可点“强制挂断”立即释放线路（已聊内容照常生成回顾）。注意：刚装好还没发起过通话时，部分来源服务显示为空属于正常现象；另外“已挂断”只表示电话结束，不代表回顾已经发回 QQ。
- **速度参考**：页面里的参考耗时来自固定 HTTPS、停顿 1400 毫秒、Android QQ 环境的实测（说完到听见第一声中位 **3.95 秒**），用来帮你判断大致水平，不是对所有设备的硬性保证。耗时拆成 7 段（停顿等待、音频上传、语音识别、模型回复、语音合成、音频下发起播、总计说完到首声）；因为部分环节是并行重叠的，各段数字直接相加会大于总耗时。
- **一键测试**：点击后会用内置的一段短录音真实调用一次语音识别、电话模型和语音合成，可能会产生少量接口费用；通话期间不能点击，两次测试间隔至少 30 秒。它只检查服务通不通和快不快，不能替代手机实际打通一轮。

## 隐私与数据

手机浏览器只会在你明确授权后开启麦克风；本地人声检测使用随包自带的开源模型在手机浏览器里直接运行，不会把录音发给额外的人声检测服务。通话音频经 HTTPS 加密传到你的 AstrBot 服务器后，会由你配置的语音识别服务转成文字，再连同聊天记录、机器人设定与工具说明发给聊天模型，回复文字发给语音合成服务朗读，挂断后发给原聊天模型整理回顾；如果你在 AstrBot 里启用了其他插件或工具，它们也可能按配置参与处理。各服务商的留存、训练与跨境数据政策请自行查阅对应官网协议。

使用临时隧道时流量会经过 Cloudflare，使用固定 HTTPS 时流量经过你自己配置的服务器和反向代理。HTTPS 保护传输过程不被窃听，但服务器和外部服务商仍需处理你的对话内容。所有 API 密钥都只保存在 AstrBot 服务端，手机网页只拿短期有效的通话凭据，切勿把通话链接转发给他人。

插件会在 AstrBot 数据目录 `data/plugin_data/astrbot_plugin_bot_call/calls.sqlite3` 中保存通话基本信息、语音转成的文字、机器人回复、播放进度、回顾状态、临时音频和耗时记录。它不是永久录音库，但也不会在挂断瞬间马上删掉声音：在通话回顾彻底发回并写完记忆前，会保留完整材料以防异常丢失；全部完成后默认保留 **7 天**（可在控制面板“音频材料保留天数”里调整，填 `0` 表示不自动清理），到期后会自动分批清理临时合成音频与未识别失败原音，并在空闲时回收数据库空间，文字记录、播放进度与回顾正文会继续保留。服务器管理员仍需妥善保管服务器权限与数据备份。

## 常见问题

| 遇到的问题 | 建议按顺序排查 |
| --- | --- |
| 链接打不开或提示已过期 | 确认插件管理里已启用，且控制面板的“启用通话功能”开关已打开；链接 15 分钟内有效且只能用一次，过期请重新发 `/botcall`；使用临时隧道时重启会换新网址，需重新发起；固定 HTTPS 请依次核对域名解析、备案、80/443 端口、证书和手机网络（见[固定 HTTPS 配置](#固定-https-配置)） |
| 点开链接提示“当前线路正在占线” | 整个插件同一时间只接一通电话；可以等另一通挂断后直接点页面里的“点击重试接通”（原链接不会失效），或者请管理员到后台“评测与诊断”页强制挂断当前占线通话 |
| 机器人开口前一直显示“工具处理中…” | 机器人正在联网搜索或调用其他插件工具，这期间暂不支持插话以免打断任务，等它开口播报或处理完再说话即可 |
| 提示接入被拒、403 或实时连接连不上 | 刷新控制面板看“最近一次接入拒绝”：先确认显示的来源 IP 确实是你的反向代理，再把它准确填进可信代理；确认访问域名和公开访问地址完全一致、只套了一层正确的 HTTPS 标记头，并且反向代理开启了 WebSocket 转发（见[固定 HTTPS 配置](#固定-https-配置)） |
| 听不到声音 | 先查手机媒体音量、蓝牙设备和浏览器是否拦截了自动播放（按页面提示点一下即可恢复声音）；再确认语音合成服务已启用、音色配置无误且有余额，并确认 AstrBot 运行环境里有 `ffmpeg` 与 MP3 编码支持；可用通话页“声音检查”和后台“一键测试”快速判断是服务商问题还是手机播放问题 |
| 不能自动断句或不能插话 | 检查是否通过 HTTPS 打开且已允许麦克风权限、页面是否保持在前台、有没有点到静音；如果控制面板把录音方式改成了兼容模式（`legacy`）或老旧浏览器不支持持续收音，则无法自动插话。在控制面板确认录音方式和朗读时插话均为“自动（auto）”，保存重载后再开新通话；环境有外放回声时建议戴耳机 |
| 第一次打开加载慢 | 新设备首次进入需要下载约 6 MB 的本地人声检测文件，下完会自动缓存；加载时不要反复刷新，可在后台“评测与诊断”页查看下载耗时 |
| 提示语音识别（STT）未配置或不可用 | 在控制面板“电话专用 STT”里选一个已启用的语音识别服务，或在 AstrBot 里为原 QQ 聊天选好语音识别服务；顺便核对接口地址、模型名和密钥。注意：只是添加了服务不等于会话已经选用 |
| 第一句等很久（十几到二十多秒） | 打开后台“评测与诊断”页看耗时拆分和提示：最常见一是聊天模型开了“深度思考”（建议在控制面板给电话单独指定关闭思考的快速模型）；二是实时语音合成连续失败（如果服务器需代理联网，需配好 HTTP/HTTPS 代理，SOCKS 代理下只能整句播报；若所选语音服务不支持实时音频流或拒绝请求，系统会自动切回整句播报并避开重复等待） |
| 选了模型或语音服务却没生效 | 如果你是手动改配置文件，需要填 AstrBot 里的服务条目标识（而不是厂商模型名），更推荐直接在控制面板下拉选择，且条目必须是启用状态。聊天模型的“思考模式”需在 AstrBot 对应的模型设置里关闭，插件不会代关。通话回顾用的是原聊天模型，电话专用模型有余额不代表原模型也有余额 |
| 感觉等待偏长，或者话没说完就被截断 | 先到“评测与诊断”页看慢在哪一段；控制面板里的“自动断句停顿时长”推荐设为 `1400` 毫秒（设太短容易截断说话，设太长会多等一会儿）；如果是模型回复慢，检查是否开了思考或带入了过多聊天记录/工具 |
| 挂断后没收到回顾，或一直卡在整理 | 打开“评测与诊断”页查看回顾、记忆写入和消息发送各自的状态与错误提示；重点检查原聊天模型是否还有余额、QQ 发送消息是否正常，确认后可直接在诊断页手动点重试 |
| 切到后台或锁屏回来后不收音了 | 回到页面后点击“继续”重新恢复麦克风；不要看到机器人还在播报声音就以为麦克风也已经恢复 |
| 打电话时少了一些管理员才能用的工具 | 电话严格沿用原 QQ 聊天的管理员身份判断（AstrBot 的 `admins_id` 配置）；如果你用的是官方 QQ 机器人等平台，请确认把该平台下你实际的发送者 ID（例如 OpenID）填进了管理员名单 |
